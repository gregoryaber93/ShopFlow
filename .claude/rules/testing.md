# Testing rules

## Tooling

- xUnit v3 on Microsoft.Testing.Platform: filter with `--filter-namespace`, `--filter-class`, `--filter-method`,
  `--filter-not-namespace`; `dotnet test --solution ShopFlow.slnx` or `--project <path>`.
- Assertions with Shouldly (`result.ShouldBe(...)`). For our own ports use hand-written fakes and the in-memory
  adapters from `*.Testing` projects (`InMemoryOrders`, `FakeOrchestrationContext`, ...); a fake that grows logic is a
  sign the port is too wide. NSubstitute (global using in test projects) is reserved for SDK types that cannot be
  faked otherwise: Cosmos `Container`/`TransactionalBatch`, `DurableTaskClient`, `IMessageSettlement`.
- Time with `FakeTimeProvider` (`Microsoft.Extensions.TimeProvider.Testing`), never `Thread.Sleep` or real delays.

## What goes where

| Test type | Project | Rule |
|---|---|---|
| Domain and application | `src/Services/<Ctx>/tests/*.UnitTests` | no I/O, no host; one behavior per test |
| HTTP API | `*.Api.Tests` | `WebApplicationFactory`, real pipeline, fake ports |
| Integration | `*.IntegrationTests` | Testcontainers / emulators; skip unless `SHOPFLOW_RUN_INTEGRATION_TESTS=1` |
| Architecture | `tests/ShopFlow.Architecture.Tests` | NetArchTest rules + a canary test that proves each rule can fail |
| Contracts | `tests/ShopFlow.Contracts.Tests` | conventions, JSON schema snapshots, topology consistency |
| Consumer-driven contracts | `tests/ShopFlow.Pact.Tests` | consumers first (generate pacts), then providers |

## Conventions

- Test names are sentences with underscores: `Confirming_twice_is_a_silent_no_op`.
- Test the behavior the repository is teaching: idempotency (handle the same message twice), out-of-order delivery,
  compensation of a step that never ran, concurrency conflicts (ETag), failure classification (transient vs permanent).
- No test may call Azure or any network service outside localhost. Integration tests use emulators in Docker.
- Snapshots (`*.approved.json`) and pacts are regenerated by tests, never edited by hand.
- Exit code 8 from MTP means zero tests ran: in CI it is ignored only for the filtered-out Pact project.
